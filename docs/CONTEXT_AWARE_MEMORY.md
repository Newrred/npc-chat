# 문맥 기반 기억 선택 v1 — 2026-09-08

## 적용 범위

기존 FastAPI → SQLite → llama.cpp 구조를 유지하면서 기억 선택을 보강했다. 별도 모델, 임베딩, 벡터 DB, LangChain, 추가 생성 호출은 없다. 대사 생성과 일반 기억 후보 추출에는 기존 LLM을 계속 사용한다. 이번에 규칙으로 처리하는 것은 검색 단서·관련성·명확한 취향 정정이다.

## 전후 동작

| 항목 | 이전 | 적용 후 |
|---|---|---|
| 검색 근거 | 현재 메시지의 단어 포함 여부 | 현재 주제 단어 우선, 명시적인 이어 말하기만 최근 사용자 발언 보조 |
| 최근 문맥 | 검색에 전달하지 않음 | 서버의 마지막 4개 메시지 안에서 가장 가까운 사용자 발언 사용 |
| 결과 | 최대 3개, 관련도 0이어도 채움 | 관련성 근거가 있는 0~3개, 무관한 후보로 채우지 않음 |
| 단어 비교 | 부분 문자열 | 제한된 조사 제거 후 단어 일치. 보리와 보리차를 같다고 보지 않음 |
| 정정 시점 | 응답 저장 뒤 일부 취향 교체 | 명확한 현재 취향 정정과 반대되는 기억·과거 발언을 생성 전 제외하고 성공 시 원자적으로 갱신 |
| 정정 대상 | 제한된 취향 문형 | 이제/지금은, 조사 없는 짧은 취향 문장 일부 보강. 질문·인용·타인 발언은 정정 근거로 쓰지 않음 |

검색 순서는 관련 단어 수, 갱신 시각, 중요도, 안정적인 ID다. 현재 메시지가 기억과 직접 일치하면 과거 주제로 후보를 채우지 않는다. 직접 일치가 없을 때 걔/그거 등의 표현 또는 일부 짧은 후속 반응에만 보조 검색을 허용한다. 근데/그런데/말고 등 명시적 전환은 보조 검색을 막는다. 여러 후보에 서로 다른 주제 단서가 걸리면 연결을 보류한다. 캐릭터 발언만으로 검색 대상을 정하지 않는다. '내 취향 기억나?'처럼 주제를 특정하지 않은 명시적 취향 조회는 취향 종류 내에서만 선택한다.

이는 일반적인 대명사 해석이나 한국어 의미 검색이 아니다. 마지막 사용자 발언이 '응'뿐이면 더 이전 주제를 추론하여 복원하지 않는다. 조사/어미·동의어 전부를 지원하지 않으며, 공통 명사로 잘못 연결되거나 표현 차이로 누락될 수 있다. 예시에서 모카/보리 같은 이름은 하드코딩하지 않는다.

## 저장·프롬프트

현재 사용자의 명확한 취향이 최우선이다. 같은 대상의 반대 취향만 기존 기억/요약/최근 발언에서 이번 프롬프트용으로 제외한다. 같은 취향을 다르게 표현한 문장은 모순으로 보지 않는다. 제외는 저장된 대화 원문 삭제가 아니다. 성공적으로 응답한 뒤 같은 취향 항목만 교체하며, 모델 실패/DB 롤백에는 이전 기억을 보존한다. 동일 턴 재전송은 기존 응답을 재사용한다. 모델이 직접 취향을 fact로 잘못 분류해도 지원 문형이면 preference로 정규화하여 중복 정정을 방지한다.

현재 모델 입력 길이 계산과 제거 순서(오래된 메모 → 선택 기억 → 오래된 문답)는 유지한다. 고정 예시, 12개 최근 메시지 보관, 50개 별도 기억 상한, 관계 수치·기분 설계는 이번에 변경하지 않았다. DB 스키마 변경과 기존 데이터 일괄 변환은 없다. 일반 거주지/직장 사실의 충돌 해결, 사건 기억·유효 기간·대체 이력, 상황별 예시 선택은 후속 범위다.

## 검증과 실제 모델 한계

격리 테스트는 직접 검색·이어 말하기·주제 전환·모호성·부분 문자열 오탐·타 사용자 격리·브라우저 이력 무시·생성 전 정정·중복 요청·실패 롤백·재시작을 포함한다. 기존 '커피 검색에 민트초코도 반환' 테스트는 새 요구에 맞게 바꾸고 민트초코 자체의 보존은 따로 확인했다. 개발 중 테스트 데이터 생성기의 session_id 누락과 보조 검색의 지나친 단서 개수 제한을 발견해 수정했다.

재현 명령:

```powershell
./venv/Scripts/python.exe -m pytest -q
./venv/Scripts/python.exe -m ruff check app tests scripts
./venv/Scripts/python.exe -m compileall -q app scripts
./venv/Scripts/python.exe scripts/evaluate_memory_retrieval.py --output .runtime/memory-retrieval-v1.json --real-model --env-file .runtime/public-test.env --model-cases 6
```

평가 원자료는 `evaluation/memory-retrieval.json`, 결과는 `docs/evaluation/memory-retrieval-v1.json`이다. 이전 검색기는 모든 사례에 3개를 반환하여 정확한 선택 집합 일치 0/12, 새 검색기는 12/12다. 이 비교는 무관한 기억 제외를 확인하는 한정된 합성 검사이며 검색 재현율 0%나 대화 품질 100%를 의미하지 않는다.

최종 자동 테스트는 484 passed (9.64s), Ruff·compileall·Git 공백 검사도 통과했다. 작업 전 기준은 435 passed였다.

동일 실행 중 9B 모델로 새 검색 결과를 넣은 6개 사례 모두 1회 시도에 유효 응답을 받았다. 대명사 맥락의 수면 문제에 공감하고, 홍차 정정을 받아들이는 응답을 관찰했다. 그러나 점심 질문에 사용자를 '유이'로 부르는 역할 혼동, 모호한 대상에 대한 불필요한 자기 언급과 정정 시 지어낸 행동 제안은 남았다. 취향 회상 1개는 기존 서버 원문 인용 보정이 적용되므로 모델 자체의 기억 능력 성과로 세지 않는다. 전후 모델 응답 A/B 비교나 자연스러움 향상을 입증한 결과는 아니다.

합성 평가 도구는 실사용 DB에 쓰지 않고 실제 방문자의 대화 원문을 사용하지 않는다. 별도로 웹 프로세스만 재시작하여 공개 링크에 적용하고, 새 검증용 방문자로 '나는 녹차를 좋아해' → '이제 녹차 싫어해' → '녹차는 내가 좋아했지?'를 확인했다. 3턴 모두 HTTP 200이며 마지막 응답은 정정된 부정 취향을 회상했다. 3턴 저장을 확인한 뒤 해당 검증용 대화방만 초기화했다. 모델 재로딩과 기존 사용자 기록 변경은 없으며 검증 3회는 일일 한도에 포함된다.
