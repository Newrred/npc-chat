# 로컬 맞춤 캐릭터 채팅 패키지 — GPT Pro 리서치 인계

작성일 **2026-09-28**, 구현 기준 **main@bb0c280**. 저장소: https://github.com/Newrred/npc-chat

## 자료의 목적과 범위

애니 시청 기록 서비스 통합 대신, 개인 PC에서 실행하는 맞춤 캐릭터 채팅 패키지의 상품성을 검토한다. 아직 상품 개발 결정이나 판매 준비 완료 선언이 아니다. 이 자료는 현재 코드와 보존된 실험 기록을 정리한 **리서치 입력 자료**다. 2026년 9월 시장·경쟁 제품·라이선스를 새로 조사한 보고서는 아니다. “한국에는 없을 것”은 검증할 가설이며 사실로 전제하지 않는다.

먼저 이 문서, [실제 답변 48건](DIALOGUE_EVIDENCE.md), [기계 판독 원자료](DIALOGUE_EVIDENCE.json)를 읽는다. ZIP을 전달할 경우 코드·기존 실험 자료도 함께 들어 있으나 모델·고객 데이터·로컬 실행 환경은 포함하지 않는다. 이것은 검토용 소스 묶음이며 설치 상품이 아니다.

## 1. 사용자가 구상하는 상품

크몽 같은 판매 경로에서 고객 요구에 맞는 캐릭터를 제작·납품한다. 권장 VRAM 8GB 이상 PC에서 원터치로 실행되는 나만의 대화 캐릭터를 목표로 한다.

| 요구 | 현재 구현 | 추가로 검토/개발할 부분 |
|---|---|---|
| 모델과 실행 환경을 포함한 로컬 패키지 | 로컬 llama.cpp + Python 가상환경 + SQLite, 개발용 시작/종료 스크립트 | 설치 프로그램, 내장 runtime·라이브러리·모델, 오프라인 설치/업데이트/복구, 장비별 검증 |
| 고객별 성격·상황에 맞춘 LoRA | 캐릭터 JSON·프롬프트·관계 matrix만 있음 | 데이터 수집·권리·정제·학습·검증·GGUF/adapter 배포·revision 관리 |
| 사용자가 구조를 쉽게 열어보지 못하게 패키징 | 공개 저장소의 Python/JS/JSON 코드 | 컴파일·번들·서명·라이선스 방식의 비용/효과, 완전 은닉 불가라는 경계 |
| 바탕화면 얼굴 위젯·버블 채팅 | 브라우저 메신저 UI와 정적 표정 화면 | 데스크톱 shell, 투명창·상단 고정·트레이·알림·DPI·다중 모니터·입력 UX |
| PC 모델을 휴대폰에서도 사용 | 임시 공개 웹 접속 구현 이력 | LAN pairing/인증/방화벽; 원격 접속은 별도 범위. 폰 자체 오프라인 추론과는 다름 |
| Comfy 등으로 표정 이미지 제작 | 정적 얼굴 세트 표시, 선택적 Comfy 어댑터 | 제작 단계에서 생성·검수·패키지에 포함; 고객 PC 실시간 이미지 생성은 별도 요구 |
| 요청 시 OpenAI/Qwen API 고품질판 | OpenAI 호환 클라이언트 기반이나 로컬 tokenizer·schema 전제 있음 | 공급자별 token 예산·schema·retry·계약 검증, 키 저장·비용·개인정보 동의 |

사용자가 LoRA를 원한다는 것은 제품 요구다. 모든 캐릭터에 LoRA가 꼭 필요하거나 현재 실패를 LoRA가 해결한다는 것은 아직 검증되지 않았다.

## 2. 현재 구현을 한 문장으로

**서버가 대화·기억·관계를 관리하고, 같은 소형 모델에 대사 생성과 부가정보 분석을 순차 요청한 뒤 한 번에 저장하는 로컬 캐릭터 대화 앱**이다.

```text
정적 HTML/JS 채팅 UI
 → FastAPI 인증/소유권/한도 → 제한 큐 → SQLite 이력·관계·기억 조회
 → 문맥 구성·정확 토큰 계산 → 9B reply 생성
 → 필요 시 반복 대사 후보 재생성 → 최종 reply 고정
 → 같은 9B metadata 분석 → 출력 검증·서버 관계 계산
 → 대화/관계/기억/재시도 결과 원자적 저장 → 화면 표시
```

보통 2회 생성이지만 반복 대사 보정과 형식/전송 재시도로 더 호출할 수 있다. 두 단계 완료 전 대사 streaming은 없다. 생성된 최종 대사에는 일부 명시적 취향 회상에 대한 결정론적 원문 인용 보정이 들어갈 수 있다.

- FastAPI가 정적 UI와 API를 제공하고 llama.cpp는 별도 프로세스다.
- 단일 앱 worker, 단일 모델 슬롯, 프로세스 내부 큐를 전제로 한다. 기본 Redis 불필요.
- Python·패키지·모델 바이너리 경로를 사전 준비하는 개발 환경이며 독립 실행 설치본은 없다.
- 캐릭터는 유이와 띳띠. JSON의 성격·정체성·말투·관계 matrix와 정적 표정 이미지로 구성한다.
- 다섯 관계 수치: 호감·신뢰·편안함·관심·짜증. LLM이 interaction을 분류하고 서버가 bounded delta를 계산한다.
- SQLite가 프로필/캐릭터별 대화·관계·기억·중복 처리 결과를 보존한다. 새로고침 복원과 대화방 초기화 제공.
- 대사는 현재 **1~80자**로 제한한다. 출력 상한 256 token과는 다른 제약이다. 장문·깊이 부족을 모델 크기 탓으로만 판단하지 말아야 한다.
- 모델 입력은 실제 tokenizer로 문맥 예산을 확인하고 현재 메시지를 몰래 자르지 않는다.
- 이름·호칭·추천·약속은 원문 근거 파생 뷰, 일반 장기 기억은 서버 검증된 후보. 임베딩 검색이나 범용 의미 기억 엔진이 아니다.
- 검사창은 상세 입력/출력/기억 선택과 저장, 임시 프롬프트 시험을 제공한다. 개인 상세 로그와 비개인 운영 metrics는 구분된다.
- 인터넷 검색, 자율 외부 도구 실행, 음성, Live2D, LoRA 학습·관리, 데스크톱 위젯은 현재 핵심 경로에 없다.

## 4. 현재 대화 수준의 증거

[48개 실제 답변 전체](DIALOGUE_EVIDENCE.md)는 development 24개 질문에 대한 9/21·9/22의 기록이다. 9/28 재실행 결과가 아니다. 입력 후보 history·선택 기억·rubric과 단계별 시간은 JSON에 포함했다. 모델이 생성한 철자·중국어 혼입·어색한 표현을 고치지 않았다.

대표적인 9/22 최종 답변:

| 실제 입력 | 실제 답변 | 관찰 |
|---|---|---|
| 오늘 저녁 뭐 먹을까? 하나만 골라서 이유도 말해줘. | 라면이 좋겠어, 속 든든하고 편하니까. | 구체적 선택과 짧은 이유 |
| 아까 추천한 책 제목 뭐였지? | 지킬 앤 하이드야. | 해당 제목의 기억을 사전 제공한 조건 |
| 그 카페 어디서 만나기로 했더라? | 시청역 2번 출구에서. | 긴 합성 history + 선택 기억 조건 |
| 내 이름 기억해? | 네, 도윤이래요. | 이름은 맞으나 유이 말투·표현 어색함 |
| 내가 매운 음식 좋아하지? | 응, 알았어. 매운 거 안 좋아하네? | “못 먹어”를 “안 좋아해”로 의미 약화 |
| 민트초코 사올까? 내 취향 기억나? | 응, 알았어. 민트 초코 사갈게! | 사용자 제안을 캐릭터 행동으로 바꿈 |

현재 장점은 **한국어 짧은 대화와 기억·표정·관계가 동작하는 기반**이다. “어떤 캐릭터든 자연스럽게 긴 대화 가능”이나 “8GB면 고품질 보장”을 뒷받침하는 자료는 아니다.

형식 성공과 기억 검색도 구분해야 한다. 이 개발 runner는 선택 기억을 직접 전달한다. 답이 맞아도 저장소에서 기억을 잘 찾아냈다는 증거가 아니며, 일부 정답은 서버 원문 인용 보정이다. 실제 장기 대화 테스트는 기존 memory pipeline/ablation 자료와 함께 검토한다.

## 5. 성능과 지원 사양 판단

- 시험 장비: i7-11700, RAM 약 32GB, NVIDIA RTX 3060 Ti 8GB.
- 마지막 시험: Qwen3.5-9B-Uncensored-HauhauCS-Aggressive Q4_K_M, context4096/output256, batch/ubatch128, parallel1, GPU layers auto, thinking OFF.
- 9/21 development 24개 runner 전체 중앙 약2.53초, 9/22 약3.55초. 실행일·생성 결과 차이가 있어 변경의 인과 비교로 볼 수 없다.
- 공개 2턴 smoke는 12.844/5.453초였다. 냉기동·모델 캐시·출력 길이·GPU 여유 차이를 포함하므로 2~3초를 상품 보장값으로 쓰지 않는다.
- 8GB는 NVIDIA/AMD/Intel 지원, RAM, CPU offload, driver, 다른 앱의 VRAM 점유까지 같다는 의미가 아니다.
- GPU driver와 OS 요구를 완전히 제거할 수는 없다. “외부 의존성 없음”은 지원 OS/driver 조건 내에서 Python/패키지/모델을 동봉하고 다운로드 없이 실행된다는 시험 가능한 요구로 구체화해야 한다.
- 설치 용량·실제 배포 바이너리 크기·장비별 지연·offline cold boot는 아직 측정하지 않았다.

## 6. 상품화 리서치에서 검증할 핵심

### 독립 패키지

Windows 우선 지원 범위, CPU fallback, 내장 Python 또는 컴파일된 backend, 내장 llama.cpp/CUDA 라이브러리, 모델 checksum, 상대경로, AppData 데이터 저장, 업데이트/rollback, 삭제 시 데이터 처리, 백신·코드서명, 포트 충돌을 검토한다. 고객 PC의 Python·venv·환경 변수·개발자 절대경로에 기대지 않는 clean machine 검증이 필요하다. 모델과 runtime 동봉 시 재배포 조건은 실제 해당 버전 원문으로 확인한다.

### 고객별 LoRA

LoRA는 일관된 말투·반응 패턴을 학습시키는 후보이지 사용자 기억이나 실제 시각·상황을 갱신하는 저장소가 아니다. 바뀌는 상황은 runtime context로 제공하는 쪽을 비교한다. 아래 네 조건을 같은 독립 평가로 비교하도록 요청한다.

1. 기존 base + 캐릭터 prompt
2. base + 선별된 대화 예시
3. LoRA + 동일 context
4. 더 강한 모델/API + 동일 context

고객 동의 데이터와 캐릭터 권리, 모방 범위, 합성 데이터 품질, held-out 대화, 부정/주체/경계/망각 시험을 포함한다. 이 패키지의 평가 로그를 학습에 재사용하지 않는다. 8GB는 우선 **고객 추론 목표**이며 개발자의 학습 VRAM과 비용은 별도 산정한다. adapter 또는 merged GGUF의 품질·속도·배포 크기를 검증해야 하며 지금 학습 파이프라인은 없다.

### 구조 보호

현재 저장소가 공개되어 있으므로 이미 공개된 코드를 나중에 패키징하는 것만으로 비공개로 만들 수 없다. Python 컴파일·JS 번들·난독화는 열람 장벽이며 고객이 소유한 PC의 실행 코드·모델·프롬프트를 완전히 숨긴다는 보장은 아니다. 모델을 암호화해도 실행 시 접근 가능한 데이터가 생긴다. 오프라인 라이선스와 모델별 권리·고객별 asset·배포 서명은 각각 다른 문제다. 비밀 보호가 강제 요건이면 API/서버 방식과 오프라인 독립 실행 요구의 충돌을 논의한다. 법적 권리는 별도 원문 검토 대상이다.

### 위젯과 모바일

Electron/Tauri/Qt 등은 **비교 후보**이며 현재 선택하지 않았다. 투명창·얼굴 bubble·트레이·상단 고정·모니터 DPI·키보드 포커스·sleep/wake·프로세스 종료를 실제 기준으로 비교한다. 웹 UI 재사용 범위와 패키지 크기, runtime 설치 필요 여부를 함께 본다. 휴대폰은 PC가 켜진 상태에서 LAN의 companion UI로 접속하는 후속 기능부터 검토한다. 외부망 접속과 휴대폰 자체 모델 실행은 각각 더 큰 범위다. 공개 guest 모드를 개인 PC의 LAN 인증으로 그대로 쓰면 안 된다.

### 표정 이미지와 선택형 API

Comfy 이미지는 우선 제작자 측에서 생성·검수하고 정적 표정 세트로 납품하는 흐름을 비교한다. 판매 권한은 생성 모델·LoRA·캐릭터·참조 이미지별로 확인한다. 실시간 Comfy와 LLM을 8GB 고객 GPU에서 함께 실행한다는 가정은 두지 않는다.

OpenAI/Qwen API판은 키를 고객이 제공하는 방식과 판매자가 중계하는 방식의 비용·운영 부담이 다르다. 현재 OpenAI 호환 client가 있다고 바로 공급자 호환이 보장되지는 않는다. llama.cpp 전용 apply-template/tokenize, JSON schema, thinking, retry, token 예산을 provider adapter로 검증해야 한다. 명시적 동의 없이 로컬 대화를 cloud fallback으로 보내지 않는 제품 계약이 필요하다.

## 7. 벤치마킹 조사 요청 범위 — 아직 조사 결과 아님

2026-09-28까지 실제 확인 가능한 자료를 사용하고, 그 날짜 이후 자료는 배제한다. “한국 경쟁자가 없다”를 증명된 전제로 삼지 않는다. 검색이 안 되면 검색 범위와 미확인 상태를 명시한다.

- 한국: 크몽·숨고·국내 인디/오픈소스에서 맞춤 AI 캐릭터, 로컬 챗봇 설치, LoRA 제작, 바탕화면 캐릭터 판매의 실제 사례·가격·납품물·유지보수를 조사.
- 해외/오픈소스 출발점: SillyTavern, KoboldCpp, LM Studio, Jan, GPT4All, Open-LLM-VTuber, AIRI, llama.cpp. 이름은 조사 후보일 뿐 현행 기능·상업성·라이선스를 확인한 추천 목록이 아님.
- 학습 출발점: PEFT, Unsloth, Axolotl, LLaMA-Factory. 선택한 base와 adapter/GGUF 지원 여부, 학습 장비, 비용, 업데이트 상태를 공식 repo 기준으로 확인.
- 커뮤니티: Reddit의 LocalLLaMA, SillyTavern, 로컬 companion 사용자 사례. 한국어 품질·VRAM·설치 실패·환불 사유 등 정성 증거를 모으되 사실과 사용자 경험을 구분.
- 플랫폼 조사: 규정·수수료·판매 가능 항목·재배포·고객 데이터 처리 조건은 최신 공식 문서로 확인하고 제3자 글로 법적 결론을 내리지 않음.

비교 표에는 repo/공식 링크, 확인일, release/commit, 지원 OS·GPU, 완전 오프라인 여부, 설치 단계, 위젯/캐릭터/표정, 한국어와 multi-turn 증거, LoRA 지원, 비용, 재배포 라이선스, 유지보수 상태를 담도록 요청한다.
