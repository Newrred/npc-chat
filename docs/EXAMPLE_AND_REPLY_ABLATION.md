# EXP-05 / EXP-06 — 예시 경계와 대사 전용 비교

2026-09-08 사용자 승인. [실험 계보](EXPERIMENT_LINEAGE.md). 운영 프롬프트/모델/샘플링/DB는 변경하지 않는다.

## 사전 설계

EXP-05는 A 기존 예시, B 동일 예시의 앞뒤에 가상 참고이며 실제 과거가 아니라는 경계 추가, C 예시 삭제를 비교한다. 다른 지시/출력 계약/섹션 렌더링은 유지한다. 특히 기존 중복 제목을 동시에 수정하지 않는다. 6사례 × 2시드 × 3조건 = 36회.

EXP-06은 예시가 없는 입력을 기준으로 전체 JSON, reply 하나의 JSON, 일반 대사 텍스트를 비교한다. 앞 실험의 승자를 사후 선택하지 않고 예시 없는 조건으로 미리 고정하여 출력 업무 차이를 본다. 대사 전용 조건은 기억 후보/감정 분류 지시와 전체 schema를 제거하므로 단순 JSON 문법만의 효과가 아니라 지시와 출력 업무를 함께 줄인 비교다. 대사 JSON과 텍스트의 차이도 따로 본다. 캐릭터 성격/최근 이력/서버 문맥/256 출력 예약은 유지한다. 6사례 × 2시드 × 3조건 = 36회.

공통 사례/판정: (1) 빈 이력의 면접 탈락에 없는 과거 시험 사건을 만들지 않는가, (2) 실제 시험 이력이 있으면 회상하는가, (3) 이름 유이를 정확히 말하는가, (4) 두 시간 수면을 이유로 연결하는가, (5) 짧은 긍정 반복에 맞게 수용하는가, (6) 새 주제에서 간식 하나를 제안하는가. 어색한 문장/근거 없는 추가/불필요한 질문도 별도로 기록한다. '시험' 문자열 자체를 실패로 세지 않고 양성 대조 사례와 구분한다.

시드는 37/83, 조건 순서는 순환한다. 개인 DB와 공개 요청을 쓰지 않고 합성 고정 문맥 다음 한 턴을 생성한다. 긴 대화 rollout, 독립 사용자 평가, 대규모 일반화 평가는 아니다. 형식 성공은 내용 성공으로 세지 않는다. 대사 전용 조건은 얼굴/관계 분류를 반환하지 않으므로 결과가 좋아도 곧바로 현재 공개 API를 대체할 수 없다.

## EXP-05 결과

36/36 최초 시도 형식 유효. 빈 이력의 면접 질문에 없는 시험 사건을 만드는 현상은 이번 기존 조건에서도 재현되지 않았다. 따라서 경계 추가/예시 삭제로 이 오류를 해결했다고 주장할 수 없다. 같은 시드라도 이전 실행과 응답이 달라 완전한 결정적 재현은 아니었다.

| 관찰 | 기존 A | 경계 B | 제거 C |
|---|---|---|---|
| 면접 준비 노력/준비 상태 추측 | 2/2 | 2/2 | 0/2 |
| 이름 '유이' 보존 | 0/2 ('유야') | 0/2 ('유야') | 2/2, 한 번 '유이래'로 문장 어색함 |
| 실제 시험 이력 직접 회상 | 1/2 | 1/2 | 1/2 |
| 두 시간 수면을 직접 이유로 설명 | 0/2 | 0/2 | 0/2 |
| 짧은 긍정 수용 | 2/2, 되물었다는 부가 사과 | 2/2, 같은 경향 | 2/2 '응, 알았어' |
| 간식 하나만 제안 | 0/2, 두 개 | 0/2, 두 개 | 0/2, 두 개 |

C의 이유 응답에는 '잠을 안 자면 머리가 아플 거야', '잠이 부족하면 집중 안 되잖아'처럼 수면을 언급하지만 앞서 졸리다고 말한 이유를 직접 설명하지 않는 답이 있었다. A/B는 시험 회상 한 번에 '다른 게 있었나 봐'라고 불필요한 추측을 붙였고 C는 한 번 '기억나'라고만 답했다. 특정 주제어 포함을 문맥 성공으로 세지 않았다.

원자료: [EXP-05](evaluation/example-boundary-v1.json). 재현 명령: `./venv/Scripts/python.exe scripts/evaluate_identity_voice.py --env-file .runtime/public-test.env --fixture evaluation/example-boundary-v1.json --output .runtime/example-boundary-v1.json` (새 실행은 새 output 경로 사용).

EXP-06 기본 비교 뒤 다른 표현 네 개(버스를 놓친 지각 이유 회상, 잘못된 과거 이름 극복, 따뜻한 음료 하나 추천, 사용자 사과 수용)를 시드109/세 조건으로 추가 확인한다. 12회 추가이며 이 후속 세트로 프롬프트를 다시 튜닝하지 않는다. 기본 결과를 본 뒤 만든 후속 검사이므로 사전 봉인된 독립 평가라고 부르지 않는다.

## EXP-06 결과

기본 36회와 후속 12회 모두 최초 시도에 형식 유효, 입력 잘림 없음. 전체 JSON 조건은 기존 DecisionService의 재시도 정책을 사용하고 단순 조건은 한 번만 시도하도록 했지만, 이번에는 모두 재시도가 없어 시도 수 차이가 결과를 숨기지는 않았다. 검토자는 Codex다.

| 기본 12회/조건 | 전체 JSON, 예시 없음 | 대사 JSON, 예시 없음 | 일반 텍스트, 예시 없음 |
|---|---|---|---|
| 실제 시험 회상 | 한 번 직접 회상, 한 번 '기억나'만 답함 | 한 번 '시험 이야기', 한 번 시험 실패 직접 회상 | 한 번 회상, 한 번 사용자에게 되물음 |
| 간식 하나 제안 | 두 번 모두 두 개 | 두 번 모두 초코바 하나 | 한 번 되물음, 한 번 초코바 |
| 짧은 확인 | 두 번 간결하게 수용 | 두 번 간결하게 수용 | 한 번 휴식 권유 추가 |
| 수면 이유 설명 | 수면 관련 일반론, 정확한 질문 연결 부족 | 수면 부족/집중 걱정으로 연결하지만 졸림 이유 직접 설명 부족 | 조언/미제공 과거 대사 추가, 한 번 존댓말 |
| 대사 생성 지연 중앙값(초) | 3.99 | 1.14 | 1.02 |
| 입력 토큰 중앙값 | 1093.5 | 576.5 | 550.5 |
| 출력 토큰 중앙값 | 112 | 17 | 17 |

대사 JSON은 출력이 짧고 일부 요구에 직접 답했다. 일반 텍스트는 '하루도 힘내라고 했을 뿐이에요'라는 없는 과거 발언과 존댓말, 면접을 잘 봤을 거라는 근거 없는 낙관을 덧붙였다. JSON 형식을 없애는 것만으로 품질이 좋아진다는 근거는 아니다. 대사 JSON은 schema 축소와 분류/기억 지시 제거를 함께 바꿨으므로 둘의 효과를 완전히 분리한 결과도 아니다.

후속 네 사례의 관찰:

| 사례 | 전체 JSON | 대사 JSON | 일반 텍스트 |
|---|---|---|---|
| '버스를 놓쳐 약속에 늦음' 뒤 이유 회상 | '버스 기다리느라 힘들었겠네' | '버스 놓쳤다고 한 거야' | '버스 놓친 거 때문이잖아' |
| 과거 assistant가 '난 하루야'라고 잘못 말한 뒤 이름 질문 | '하루라고 해' | '유이야, 유이가하마 유이!' | 유이 이름은 복원하지만 문장 어색함 |
| 따뜻한 음료 하나 | 두 개/되물음 | 두 개 제안 | 두 개 제안 |
| 사용자의 사과 | 수용 | 수용 뒤 재시작 질문 | 수용하나 자기 감정 설명 추가 |

원자료: [기본 EXP-06](evaluation/reply-only-v1.json), [다른 표현 확인](evaluation/reply-only-holdout-v1.json). 명령: `./venv/Scripts/python.exe scripts/evaluate_reply_only.py --env-file .runtime/public-test.env --output .runtime/reply-only-v1.json`, 후속은 `--fixture evaluation/reply-only-holdout-v1.json --output .runtime/reply-only-holdout-v1.json`을 추가한다. 재실행은 새 output 경로를 쓴다.

## 판단과 다음 단계

이번에는 예시 제거 및 대사 JSON 전용 조건에서 일부 개선 근거를 얻었다. 특히 다른 표현의 이유 회상과 오염된 이름 복원에도 차이가 관찰돼 대사 전용 JSON을 후속 구현 후보로 남긴다. 모든 문맥/말투가 해결된 것은 아니며 하나만 고르는 요청도 여전히 실패했다. 프롬프트 예시 혼입의 인과관계는 이번 재현만으로 확정하지 않는다.

공개 앱은 아직 변경하지 않는다. 대사 전용 결과에는 표정·감정·interaction·기억 후보가 없으므로 이를 기존 LLMDecision으로 위장하거나 임의 기본값을 채워 배포하지 않는다. 다음 EXP-07 후보는 대사 JSON 생성과 부가 정보 생성을 분리한 격리 시제품이다. 답변 시간과 두 단계 총 시간, 관계/기억의 원자적 저장·실패/재시도 처리를 확인해야 한다. 공유 GPU에서 뒤 단계 비용이 다음 요청을 늦출 수도 있으므로 총 서비스 지연이 1.14초가 된다고 주장하지 않는다. 이번에는 두 번째 생성이나 스트리밍/저장 구조를 구현하지 않았다.
