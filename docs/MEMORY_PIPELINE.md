## 현재 흐름

```text
해당 방문자·캐릭터의 committed turns
  ├─ 전체 원문 대화 → 실제 토큰 예산에 들어가는 최신 연속 구간
  ├─ 명시적인 이름·선호 호칭 → 최신 값과 원문/출처 턴
  └─ 인용 제목 추천·약속/제안·명시적 약속 취소 발언 → 관련 사건 최대 3개
기존 memories 테이블 → 관련 사용자 기억 최대 3개
  ↓
Context Builder → 기존 대사 생성 → 기존 부가 정보 분석 → 원자적 저장
```

`character_relationships.history[-12:]`는 호환 캐시로 유지하지만, 원문 turns가 있으면 모델 입력의 6턴 제한으로 쓰지 않는다. 실제 llama.cpp 토큰화에서 출력256+여유64를 예약한다. 오래된 짧은 요약을 먼저 제거하고 최근 대화의 오래된 완전한 쌍부터 줄인다. 원문 대화 선택은 이분 탐색으로 토큰화 호출 수를 줄이며 반환 직전 실제 길이를 재검증한다. 이름/호칭과 관련 사건 증거는 별도 작은 영역에 유지한다. 일반 사용자 기억도 오래된 대화보다 우선하고, 대화가 전부 빠져도 초과하는 경우 낮은 순위부터 제거한다. 현재 사용자 메시지와 두 번째 단계의 고정 대사는 조용히 자르지 않는다. 필수 영역만으로 넘으면 기존 INPUT_TOO_LONG 오류를 반환한다.

## 저장과 출처

새 프로필/사건 테이블을 만들지 않았다. 이미 원자적으로 저장한 원문 turns를 읽어 별도의 **파생 뷰**로 이름·사건을 구성한다. 따라서 기존 대화도 다음 요청부터 활용하고, 추출 실패한 모델 후보를 신뢰하거나 사용자 DB를 일괄 수정할 필요가 없다. 원문이 durable source이며 프로필/사건 뷰 자체는 별도로 저장하지 않는다. 현 단계에서는 매 요청 원문을 순회하므로 대규모 사용에서는 인덱스/증분 materialization이 후속 과제다.

- 이름과 선호 호칭은 다른 key다. 명시적인 `내 이름은 …` 또는 직전 이름/정체성 질문에 대한 제한된 자기소개를 인식한다. 최신 명시적 정정이 우선한다. 현재 메시지의 정정도 해당 턴 입력에 반영한다. `…라고 불러`는 호칭을 변경한다.
- 모델이 만든 이름 후보가 틀려도 원문에서 직접 인식한 이름은 사용할 수 있다. 이름 규칙은 한국어 중심의 제한된 패턴이며 임의의 문장/별칭/언어를 모두 이해하지 않는다.
- `이름을 잊어줘` 등은 해당 프로필 값에 null을 주는 규칙이다. 원문 삭제 요청 처리와는 다르며 전체 대화 삭제는 기존 방 나가기/reset을 사용한다.
- 사건은 actor/type/quote/source_turn과 추천 제목이 있으면 value를 포함한다. **“캐릭터가 추천했다고 말했다”는 출처를 보존하며 실제 대출·구매·완료 사실을 확정하지 않는다.** 따옴표 없는 추천, 복잡한 약속 연결이나 대명사 해석은 아직 제한적이다.
- 책/소설/도서, 명시적인 약속 질문, 제목 단어 등의 단서로 관련 사건만 최대3개 선택한다. 명시적 취소 발언도 구분한다. 완전한 사건 상태 추적기는 아니며 모호한 관계는 확인 질문이 필요하다.
- 기존 사용자 memory 후보의 원문 검증은 완화하지 않았다. `memory.accepted_candidates`는 기존 memories 테이블에 반영한 후보 수다. **0이어도 파생 프로필/사건이 입력에 포함될 수 있다.** 부가 정보 JSON 출력 항목도 늘리지 않았다.

모든 원문 조회는 profile_id/character_id로 제한한다. 실패한 turn은 원문이 commit되지 않아 새 파생 기억도 생기지 않는다. replay는 이전 응답을 반환한다. reset에서 원문을 제거하면 파생 프로필/사건도 사라진다. 기존 Redis import에 원문이 없으면 남아 있는 호환 캐시만 사용할 수 있으며, 이미 유실된 원문을 복원하지는 못한다.

## 2026-09-09 Task19 — 활성 화제 기반 검색

생략 질문에서 최근 사용자 발화의 화제 종료·전환·취소 전 구간을 검색 단서로 사용하지 않는다. `작품`과 추천/선택 지칭은 가장 최근의 출처 있는 추천 하나에 연결하고, 목적지 생략 질문은 활성 시간·만남 단서가 있을 때만 약속을 검색한다. 취소는 이전 약속을, 이후 새 제안은 이전 취소를 폐기한다. 연결 근거가 없으면 사건을 0개 선택한다. 별도 저장 상태가 아니라 현재 committed history에서 매 요청 파생하므로 migration과 새 호출은 없다. 상세 검증은 ACTIVE_TOPIC_RETRIEVAL.md와 EXP-12 원자료를 본다.
