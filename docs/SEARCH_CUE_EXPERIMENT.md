# EXP-10 — 부가정보 생성에 다음 턴 검색 단서 추가

결정: 실험 구현 보존, 운영 적용 보류. 호출을 추가하지 않고 도움이 될 수 있지만 단서 누락과 오래된 주제 잔류가 있어 기본으로 켜기에는 불안정하다.

## 실험 방법
현재9B/4096/출력256/두 단계/기본 캐릭터 및 샘플링 유지. 기존 metadata와 search_cues 최대2개 추가 metadata 비교. term과 quote는 실제 예산 안에 들어간 모델 입력 또는 frozen reply의 원문으로 검증한다. 단서는 사실/장기 기억으로 저장하지 않는다. 다음 한 턴의 짧은 생략 질문에만 질의를 확장한다. 추출 대상은 특정 영화·시간 규칙이 아닌 임의 주제지만 생략 판정은 아직 제한된 허용표다. 원문 존재는 의미적 관련성/사실성을 보장하지 않는다. 모델 자체 발언에도 잘못된 내용이 있을 수 있다.

합성 대화에서 첫 턴은 원문이 있는 상태로 답변+metadata를 생성하고, 다음 턴에는 처음 원문을 제거한 뒤 직전 대화와 검색한 기억만 전달했다. 원문 제거는 통제 조건이며 자연적인 토큰 밀림이나 장기 단서 누적을 검증한 것은 아니다. 실제 source_views/retrieve 경로를 사용했다. 사용자DB/운영 캐릭터/설정 변경 없음. seed109/211,5범주×2조건×2seed=20개 2턴 실행(80모델 호출),추가 timed4개 2턴 실행(16호출). 총48턴/96호출,각 턴2회이며 재시도 없음. 초기 직렬화 오류로 중단된 baseline2턴4호출은 집계 제외, 당시 도구로그에 보존.

## 결과
|사례|기존 검색|단서 추가|
|---|---|---|
|영화 정한 뒤 ‘그거 뭐였지?’|0/2 제목 회상|0/2,단서가 비었음|
|책 빌린다→‘그게 뭐였지?’|0/2 제목 회상|2/2 제목 회상|
|좋아하는 과일→‘뭐였지’|0/2 대상 회상|1/2 복숭아 회상,다른seed 단서없음|
|화제전환 후 명시적 저녁 질문|영화 기억 검색0|영화 기억 검색0,하지만1회 오래된 영화 단서가 남음|
|약속 근거없는8시→‘어딜?’|근거없는 집 제안 / 모름 취지|동일,1회 ‘놀라지?’라는 쓸모없는 단서 생성|
|8시 영화 제안→벌써8시→‘어딜?’|학교 / 저녁 제안|1/2 영화관,다른seed는단서없어기존과동일|

근거가 있는4종류8건에서 의미적 회상은0/8→4/8. 작은 집합에 대한 수동 판정이며 일반 성능 지표가 아니다. 화제전환에서 과거 영화단서가 남았지만 명시적 질문에는 gate가 확장을 막았다. 이 결과는 애매한 후속 질문에서도 안전하다는 증거가 아니다. 서버의 원문 존재 검증으로 허구의 quote/term은 걸러도 오래된 진짜 원문의 부적절한 재사용은 막지 못한다.
