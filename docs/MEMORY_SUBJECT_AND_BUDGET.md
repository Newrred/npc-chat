# 기억 주체와 문맥 예산 보호

기준: 2026-09-11, Task25 / EXP-18.

Task24 뒤에 남은 외부 검토의 두 결정적 문제를 현재 구조 안에서 수정했다. 모델 호출, 프롬프트 역할, DB schema와 외부 API는 바꾸지 않았다.

## 1. 일반 fact의 주체 보존

수정 전 `친구는 부산에 살아`라는 사용자 원문에 대해 모델 후보가 `부산에 살아`만 반환해도 부분 문자열 검사를 통과했다. 이후 사용자 기억처럼 전달될 때 친구와 사용자의 사실을 혼동할 수 있었다.

수정 후 fact 후보가 원문 중간에서 시작하고 그 앞의 같은 절에 `은/는/이/가`로 표시된 명시적 주체가 있으면 후보를 거부한다. `친구는 부산에 살아` 전체 후보와, 원문 자체가 `부산에 살아`인 직접 발화는 계속 허용한다. 원문에 없는 주체를 서버가 추측하거나 다시 쓰지 않는다.

## 2. 직전 대화 최소 영역

수정 전 예산이 부족하면 일반 기억보다 최근 대화가 먼저 제거돼 마지막 대명사·질문의 선행사까지 사라질 수 있었다.

수정 후 오래된 요약을 먼저 제거하고, 최근 이력은 최신 완전한 user/assistant 1쌍까지 줄인다. 그 상태에서도 초과하면 일반 선택 기억, 출처 기반 evidence 순으로 제거한다. 필수 영역만 남아도 초과할 때에만 마지막 대화쌍을 제거한다. 현재 사용자 입력, system 규칙, metadata 단계의 고정 reply는 계속 자르지 않는다.

## 3. 긴 evidence의 제거 가능성

profile/episode 최대 5개라는 개수 제한만으로는 하나의 긴 quote를 제한하지 못했다. 수정 후 evidence도 낮은 우선순위 항목부터 제거 가능한 예산 단위로 처리한다. JSON 문자열을 중간에서 잘라 의미나 문법을 훼손하지 않고 항목 전체를 제외한다. 반환 직전 실제 tokenizer 길이 재검증은 유지한다.

## 검증

- 수정 전 관련 기준선: 54 tests 통과.
- 새 합성 probe 3건에서 주체 생략 수용, 일반 기억의 직전 pair 우선, 긴 evidence의 `INPUT_TOO_LONG`을 각각 실패로 재현.
- 최초 예산 수정에서 최근 이력을 0개로 만든 뒤 음수 분기값이 반복되는 오류를 긴 500턴 테스트가 발견했다. 제거 가능한 pair가 실제 1개 이상일 때만 이분 탐색하도록 수정했다.
- 수정 후 확장 관련 검사: 110 tests 통과.
- 전체: 599 tests 통과. Ruff와 Python compileall 통과.
- 실제 llama.cpp apply-template/tokenize에서 3776 입력 예산을 사용해 75 tokens, 직전 pair 보존, 긴 evidence 제거를 확인.
- 실제 서버 재시작 후 model alias, web live, admin ready, public root를 확인.

이번 변경은 정보 귀속과 입력 선택의 결정적 안전성을 높인다. 모델이 저장 근거를 자연스럽게 활용하는 정도와 일반 대사 품질을 입증하는 생성 실험은 아니다. 주체 표시는 제한된 한국어 조사 규칙이며 복잡한 인용·다중 절의 의미 분석기는 아니다.
