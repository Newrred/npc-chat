## 구현

- 규칙 1.0: 호감·신뢰·편안함·관심·짜증의 다섯 값, 총점 0..100, 실제 적용 변화 -3..3. 계약의 12종 분류/강도와 반복·짜증·놀림 보정 적용. 초기값 0/30/30/30/0은 캐릭터 설정으로 교체 가능하다.
- LLM은 분류만 제안한다. legacy 모드에서도 모델 점수는 무시하고 중립 분류로 연결한다. 새 API의 relationship values/delta/reason_codes/rule_version과 기존 호감도 필드를 함께 반환한다.
- SQLAlchemy 2/Alembic schema 0001, 로컬 SQLite WAL, profile/session/관계/turn/기억/이전 기록. 관계·기억·이력·정규화 decision·응답·중복방지 키를 짧은 단일 트랜잭션에 저장한다.
- 하나의 전역 추론 큐(활성 1, 대기 8, 대기 제한 30초)가 동일 프로필의 다른 세션까지 직렬화한다. DB 쓰기 잠금은 모델 호출 중 유지하지 않는다. DB 버전 검사와 고유 키를 추가로 사용한다.
- 동일 profile/character/client_turn_id + 동일 내용은 저장한 응답 그대로 반환한다. 내용 또는 comfy 옵션 변경은 409. 첫 채팅 전에 /api/session을 만들고 브라우저에 저장한다. 실패 후 같은 메시지는 같은 ID/옵션으로 수동 재시도한다. 미완료 메시지가 있으면 먼저 재시도하도록 유지한다.
- 오래된 flat 요청은 호환되지만 turn ID 없는 요청은 중복 보장을 받을 수 없다. 브라우저 history는 보내지 않으며 서버도 이를 신뢰하지 않는다.
- 영속 최근 이력 12메시지, 모델 전달 최근 4메시지, 순환 발화 요약 400자, 후보 최대 2개, 저장 기억 50개, 검색 상위 3개. NFKC/공백/대소문자를 정규화한다. 현재 사용자 발화의 정확한 부분문자열만 기억으로 채택한다. confidence 1은 출처 일치 표시이며 사실의 객관적 진실성을 뜻하지 않는다.
- reset은 프로필 ID를 교체하고 과거 세션을 무효화한다. delete/reset은 관계/turn/기억을 제거한다. 이전 완료 기록은 남겨 같은 Redis 원본이 되살아나지 않게 한다. 이 기능은 저장소 계층이며 사용자용 삭제 화면은 아직 없다.
- OS 파일 잠금으로 같은 DB를 쓰는 두 번째 앱/worker를 거부한다. 기본 실행기·doctor·readiness는 SQLite+LLM만 사용한다. Redis 설치는 requirements-redis.txt의 명시적 선택 기능이다.

## 이전 및 실제 실행 검증

기존 웹 프로세스만 소유권 확인 후 중지하고 모델은 유지했다. `.runtime/backups/phase03-legacy-20260907.json`에 기존 Redis 1건을 내보냈다. 원본 Redis 키/TTL은 수정하지 않았다. dry-run 임시 DB 검증 후 1건 이전, 재실행은 0건 이전/1건 중복으로 확인했다. 원본과 호감도/이력/flags 일치를 검사했으며 원문은 출력하지 않았다.

실제 4B 모델 + 임시 SQLite 8턴: 모두 HTTP 200, 1.281~2.563초. 요약 갱신 2회, 후보 채택 0건. 이 결과는 기억 기능의 실사용 품질 달성을 뜻하지 않는다. 합성 결과는 무시된 `artifacts/quality/phase03-real-smoke.json`에 저장했다.

처음 실모델 연결에서는 system 메시지 두 개를 지원하지 않는 모델 템플릿 때문에 500이 발생했다. 단일 첫 system 메시지에 서버 문맥을 합치고 회귀 테스트를 추가해 해결했다. 테스트 중 SQLite 연결 미종료로 발생한 Windows 파일 잠금 오류도 contextlib.closing으로 수정했다. 신규 lint E402는 CLI 경로 초기화의 명시적 예외로 정리했다.

## 제한 및 다음 작업

현재는 한 PC/한 앱 인스턴스/한 worker 전용이다. profile/session ID는 로컬 접근 식별자로 계정 인증을 대체하지 않는다. 원격 공개는 아직 하지 않는다. 대화 원문은 로그 대신 로컬 DB에 저장되며 삭제 전까지 유지된다. 백업에도 대화가 있으므로 .runtime 밖 공유에 주의한다.

2048 문맥에서 긴 입력/이력은 실패할 수 있다. 토큰 기반 예산, 모델에 전달되지 않는 중간 이력의 요약 연결, 기억 후보의 재현율/정정 충돌 해결, 말투·공감·사실성, 사용자용 초기화/오류·재시도 화면은 Phase 04의 다음 작업이다. 후보 저장은 엄격하여 유용한 바꿔 말하기도 버릴 수 있다. 취소가 commit 시작 전에 관측되면 저장하지 않으며 commit 시작 이후 연결이 끊기면 저장될 수 있다. 이때 같은 ID로 재시도하면 중복 없이 확인한다.

개발 변경은 아직 커밋·푸시하지 않았다. 상세 백업/복구 절차는 DATABASE_OPERATIONS.md 참고.
