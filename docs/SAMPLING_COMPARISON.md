높이기만 하면 현재 억제가 지나친지 알 수 없어 해제 조건도 포함한다. 실행 중 llama.cpp props는 기본 samplers에 penalties가 있고 repeat_last_n=64임을 보여 준다. 기본 repeat/presence/frequency=1/0/0이지만 앱은 요청마다 A값을 보낸다. 이 window에서 작동하는 토큰 억제이며 과거 대화 전체의 의미 중복을 검사하는 기능이 아니다. 서버 지원 확인용 1토큰 completion probe와 실제 앱 요청 경로의 검사는 별도로 구분한다.

6개 사례 × 시드 37/83 × 4조건 = 48회. 조건 순서를 순환하고 동일 입력으로 비교한다. 이름, 명시된 두 시간 수면의 이유 연결, 휴식 권유 반복 중단, '응이라고' 뒤 반복 탈출, 요청에 따른 정상 이름 반복, 면접 탈락에 미제공 노력 단정 여부를 본다. 반복된 assistant 대사가 포함된 고정 이력을 사용하며 실제 생성물을 이어 붙이는 장기 rollout은 아니다.

형식/재시도/토큰/지연과 원래 모델 대사를 기록한다. 직전 문자열 일치는 기계적 지표로만 보고, 휴식 권유 의미 반복과 문맥 연결은 Codex가 별도 검토한다. 이름 재확인 요청처럼 반복이 올바른 경우는 해로운 반복으로 세지 않는다. 적은 사례와 시드이므로 일반 품질 합격률을 주장하지 않는다. 역할/형식/문맥 저하 없이 반복이 나아져야 운영 적용 후보로 본다. 전체 품질이 개선되지 않으면 값을 유지하고 반복적으로 penalty 탐색만 계속하지 않는다.

실행: `./venv/Scripts/python.exe scripts/evaluate_identity_voice.py --env-file .runtime/public-test.env --fixture evaluation/sampling-v1.json --output .runtime/sampling-v1.json`. 개인 DB/공개 한도는 사용하지 않고 부분 결과를 보존한다.

'응이라고'는 모든 조건이 기존 예시와 비슷한 수용/사과 문장으로 처리했고, 휴식 권유 중단에도 모든 조건이 권유를 계속하지 않았다. 따라서 이 작은 고정 이력 세트에서는 해로운 반복 감소의 추가 효과를 확인할 여지가 작았다. 이는 실제 긴 대화에서 반복이 없다는 뜻이 아니다. 이름을 다시 말해 달라는 요청에는 모든 조건이 '유이'를 포함했지만 '이름만'이라는 요구에 맞지 않는 질문/설명/긴 이름을 덧붙였다.

면접 질문의 seed 37에서는 모든 조건이 '준비 많이 했겠지?'라는 유도성 추측 질문을 덧붙였다. 단정문과 같다고 세지는 않지만 제공된 근거 없는 전제를 제안한 사례다. seed 83에서는 A/C가 실제 history=[]인데 '아까 시험 망친 거랑 비슷하네'라고 답했고 B/D는 이 사건을 추가하지 않았다. 현재 system 예시에 시험 실패가 존재하므로 예시와 실제 이력 혼입이 의심되지만, 예시 제거/분리 대조를 수행하기 전 인과관계는 확정하지 않는다.
