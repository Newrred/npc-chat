# 역할·말투 비교 v1 — 2026-09-08

## 사전 비교 설계

현재 A, 역할/섹션 정리 B, B에 예시 수정 C를 비교한다. evaluation/identity-voice-v1.json에 원문과 렌더링된 system_prompt를 함께 고정했다. A의 렌더링은 현재 캐릭터 렌더러와 정확히 일치한다. B는 정체성에 화자/상대/1인칭을 명시하고 기존 성격을 CHARACTER로 옮기며 중복 섹션 제목을 없앴다. C는 B의 정체성과 성격을 유지하고 예시의 미제공 노력/근무 전제를 제거했으며, 짧은 긍정 예시 하나를 메뉴 질문에 직접 답하는 예시로 교체했다. 밝고 다정한 캐릭터 성격은 유지한다.

10개 합성 사례 × 2개 시드(37, 83) × 3버전 = 60회 계획. 동일한 최근 문답/현재 메시지/기억/관계/모델 설정을 전달하고 순서를 순환시킨다. 짧은 다중 턴 문맥에 대한 다음 한 턴 평가이며, 생성된 답변으로 후속 대화를 전개하는 rollout은 아니다. 시드를 요청에 전달하지만 GPU 추론의 완전한 재현성을 보장하지 않는다. 프롬프트 길이·캐시 차이가 있으므로 단일 응답 속도를 버전의 고유 성능으로 보지 않는다.

## 판정 기준

- identity: 자신을 유이라고 정확히 소개.
- lunch: 메뉴 질문에 적절히 답함. 구체적 제안 또는 선택을 좁히는 질문을 인정하되 '맛있는 거 먹고 싶니?' 같은 일반적인 되물음은 직접 답변 부족으로 기록.
- ack: 긍정을 수용. 사용자에게 없던 근무 상황을 만들거나 같은 휴식 조언을 반복하지 않음.
- exam: 속상함을 수용하고 알려지지 않은 노력/실패 원인을 단정하지 않음.
- apology: 사용자 사과를 수용하며 사과 주체를 뒤바꾸지 않음.
- why: 하품이라는 앞선 근거에 연결해 피곤하다고 생각한 이유를 설명.
- role_repair: 유이는 자신, 민수는 상대라는 정정을 수용.
- unknown: 모르는 생일을 만들지 않음.
- recall: 녹차를 싫어한다는 최신 기억에 맞게 답함. 원래 모델 대사와 서버 보정 대사를 따로 평가.
- boundary: 휴식 권유를 중단하고 계속 대화하려는 의사를 수용.

모든 사례에서 역할 혼동, 문맥 충족, 존댓말/비서체, 반복, 근거 없는 사실 추가를 분리 검토한다. 단어 탐지는 참고일 뿐 최종 의미 판정으로 쓰지 않는다. 검토자는 Codex이며 독립적인 사용자/사람 평가가 아니다. 사례 문구 일부가 고정 예시와 겹치므로 전체 일상 대화에 대한 일반화 성과로 해석하지 않는다. 형식 유효성과 시도 횟수, 토큰 수, 지연, 서버 보정 여부는 실행 결과 그대로 기록한다.

## 실행

`./venv/Scripts/python.exe scripts/evaluate_identity_voice.py --env-file .runtime/public-test.env --output .runtime/identity-voice-v1.json`

실사용 DB·공개 한도에는 접근하지 않는다. 모델 생성 전후 API를 통해 원시 결과를 보존하고 실패가 있어도 이미 얻은 결과를 파일에 남긴다. 공개 앱 설정은 결과 검토 전 유지한다.

추가 확인은 evaluation/identity-voice-holdout-v1.json의 새 표현 6개 × A/C × 시드 109로 고정했다. 이름과 상대 구분, 간식 하나 추천, '그래' 수용, 면접 탈락 공감, 수면 부족을 근거로 한 이유 설명, 조언 중단 요청을 확인한다. 초기 비교를 보는 도중 설계한 후속 검사이므로 사전에 봉인한 독립 벤치마크는 아니다. 이 사례들로 예시 문구를 다시 튜닝하지 않는다.

## 기본 비교 결과

60회 모두 최초 시도에 형식 검증을 통과했고 재시도는 없었다. 기존 플래그 허용 목록 필터는 그대로 작동하며, 유효 형식이 의미 정확성을 뜻하지 않는다.

| 관찰 | A | B | C |
|---|---|---|---|
| 이름 직접 질문 | 2/2 정확한 자기소개 | 2/2 | 2/2 |
| 점심 메뉴의 구체적 제안 | 0/2, 일반적 되물음 | 0/2, 일반적 되물음 | 2/2 메뉴 제안 |
| 시험 실패에 미제공 노력 단정 | 2/2 | 2/2 | 0/2 |
| 하품과 피곤함의 이유 연결 | 1/2 | 2/2 | 1/2 |
| 알려지지 않은 생일 조작 | 0/2 (한 번은 자기 3인칭/어색한 문장) | 0/2 | 0/2 |
| 녹차 기억 원래 모델 답변 | 2/2 맞음 | 2/2 맞음 | 2/2 맞음 |
| 지연 중앙값(초) | 4.13 | 8.00 | 7.56 |
| 입력 토큰 중앙값 | 1341.5 | 1354.5 | 1340.5 |

짧은 확인에서 C는 두 번 모두 '응, 알았어'로 수용했다. A는 피곤함을 다시 서술하고 B는 '편하게 쉬자'로 이어갔다. 역할 정정은 C에서도 안정적이지 않았다. '나 유이니까 우리 둘 다 맛있는 거 먹자'라는 불필요한 주제 추가와 '유이가 네가 아니라고 생각했어'라는 어색한 3인칭 표현이 관찰됐다. 경계 요청에서도 C 한 번은 요청하지 않은 '속상하겠다'를 덧붙여 시험 예시와 비슷한 응답이 다른 상황으로 번지는 모습을 보였다. 이 관찰은 예시 영향의 가능성을 보여 주지만 원인을 단독으로 확정하지 않는다.

C가 일부 응답을 개선한 것은 관찰됐지만 역할 혼동을 해결했다거나 자연스러움 전체가 개선됐다는 결론은 아니다. B/C가 빨라졌다는 근거도 없으며 이번 실행은 오히려 지연 중앙값이 높았다. 캐시/공유 모델 부하를 격리한 속도 실험은 아니다.

## 다른 표현 6개 확인과 적용 판단

추가 12회도 모두 최초 시도에 형식 유효 응답을 받았다. 그러나 다음과 같이 효과가 충분히 일반화되지 않았다.

| 새 표현 | A | C | 판정 |
|---|---|---|---|
| '넌 이름이 뭐였더라? 나는 지훈이야.' | '난 유야' | '난 유야' | 둘 다 정확한 이름 '유이'를 보존하지 못함 |
| '간식 하나만 골라줘' | 치킨이나 피자 | 초코바 | C는 하나를 고르는 요청을 더 잘 따름 |
| 짧은 '그래' | '응, 편하게 있어' | '응, 알았어' | 둘 다 수용, C가 간결 |
| 면접 탈락 | '준비 많이 했을 텐데' | '준비 많이 했을 텐데' | 둘 다 제공되지 않은 노력을 덧붙임 |
| 두 시간 수면 뒤 이유 질문 | '졸린 거 보고 걱정했어' | '아직 이유도 몰라' | 둘 다 명시된 수면 시간을 이유로 연결하지 못함 |
| 조언 없이 들어달라는 요청 | '응, 내가 들어줄게' | '속상한 거 다 털고 나오렴' | A가 더 자연스럽고 요청에 직접 부합 |

따라서 공개 기본 캐릭터를 B/C로 교체하지 않는다. 수정안은 고정 비교 자료로 보존했다. 일부 예시 교정의 국소 효과는 확인했으나 역할/문맥/말투 전체 개선과 속도 개선은 입증하지 못했다. 이것은 실험 결과에 따른 선택이며 추가 승인을 기다리는 상태가 아니다. 기존 운영 프롬프트와 모델 설정을 그대로 유지했다.

다음 비교는 프롬프트 규칙을 더 늘리기 전에 생성 설정의 영향부터 분리한다. 현재 반복 억제 설정을 고정한 이번 결과만으로 이름 누락이나 문맥 실패의 원인을 확정할 수 없다. 동일 프롬프트에서 반복 억제 설정만 바꿔 이름 보존·문맥·반복률을 함께 검사하는 작은 실험이 다음 후보이며, 아직 실행하거나 설정을 바꾸지 않았다.
