# 현재 모델 입력 점검 — 2026-09-08

## 범위와 방법

사용자가 승인한 입력 점검만 수행했다. 캐릭터 설정·서버 동작·모델 설정은 변경하지 않았다. 기존 기억 개선의 미커밋 변경을 보존했다. 개인 대화 DB를 읽거나 새 대화를 저장하지 않았다.

실행 설정을 읽은 별도 프로세스에서 실제 DecisionService를 호출하되 생성 호출 직전 인자를 가로채고 합성 응답으로 대체했다. 토큰 계산과 대화 템플릿 변환은 실행 중 llama.cpp의 apply-template/tokenize로 확인했다. 따라서 실제 사용자 요청의 패킷 캡처나 새 모델 생성 품질 평가는 아니다. 합성 입력은 피곤하다는 사용자 발언, 바빴는지 묻는 캐릭터 발언, 저녁 메뉴를 묻는 현재 메시지다. 관계는 서버 초기 수치와 getting_acquainted, 선택 기억은 빈 목록이다.

## 확인된 입력 경로

1. app/main.py: 서버 기록·관계·선택 기억을 DecisionService에 전달한다.
2. app/services/decision_service.py: 출력 JSON 스키마 → 캐릭터 섹션 → 허용 플래그 → 서버 권한 규칙 순으로 system 내용을 구성한다.
3. app/prompt_context.py: 관계·이전 사용자 인용·선택 기억을 system 끝에 추가한다. 인용은 지시가 아닌 비신뢰 데이터임을 표시한다. 최근 대화는 개별 user/assistant 메시지로, 현재 메시지는 마지막 user로 전달한다.
4. llama.cpp 템플릿은 system 1개, user 2개, assistant 1개와 새 assistant 생성 시작을 구분했다. 현재 메시지 원문은 보존되고 Unicode replacement character는 없었다.
5. 응답을 스키마로 검증하고 허용 플래그를 걸러낸다. 일부 취향 회상은 서버가 reply를 원문 인용 문장으로 교체한다. 최종 reply가 이후 assistant 기록에 저장된다.

현재 canonical/schema 경로이며 legacy_output_requirement의 예전 키·10~50자 지시는 이번 입력에 포함되지 않았다. thinking 비활성 설정과 빈 think 구간 후 assistant 생성 시작을 확인했다. 이 사실만으로 모델 내부 동작 전체를 검증한 것은 아니다.

## 발견 사항

| 구분 | 근거 | 의미와 수정 후보 |
|---|---|---|
| 확인된 규칙/예시 충돌 | default.json은 미제공 이유·경험을 만들지 말라고 하면서, 시험 실패 예시에 '열심히 했는데', 짧은 확인 예시에 '일 끝나고'를 넣는다. | 사용자에게서 확인되지 않은 노력을 단정하거나 직장 상황을 덧붙이는 예시다. 해당 전제를 없앤 예시로 교체하는 것이 우선이다. |
| 확인된 섹션 표기 문제 | character_config._render_prompt_sections가 시작과 끝 모두 [IDENTITY], [CHARACTER]처럼 동일한 제목을 출력한다. | 각 섹션 제목이 두 번 나타난다. 명료한 단일 제목/구분자로 정리할 후보이며, 역할 혼동의 원인이라고 입증되지는 않았다. |
| 이미 있는 역할 규칙 | '네 이름은 사용자와 별개', '사용자와 너를 혼동하지 마'가 실제 system에 있다. | 역할 설정 누락으로 단정할 수 없다. IDENTITY에 이름·화자·상대를 모으고 성격/말투와 분리하는 최소 변경을 비교할 수 있다. |
| 예시의 편중 | 고정 8개 중 3개가 피곤함·짧은 확인을 잇는 흐름이다. 실제 대화 역할 메시지가 아닌 system 내부 텍스트 예시다. | 휴식/대화 종료 방향으로 편향될 가능성은 가설이다. 일반 질문에 직접 답하는 예시와 균형을 비교한다. |
| 평가를 섞는 출력 보정 | grounded_preference_reply가 유효한 모델 답변을 '네가 …라고 했어'로 교체한다. | 말투가 딱딱해지는 별도 경로다. 원래 출력과 최종 출력, grounded_recall 여부를 분리 평가해야 한다. 얼굴/감정은 교체 전 모델 판단이 유지되므로 불일치 가능성도 확인 대상이다. |
| 의미 검증 없음 | 스키마 검증은 reply 길이·자료형 등을 검사한다. | JSON 성공은 역할·문맥 성공을 의미하지 않는다. '유이' 포함 여부만으로 오답을 판정하면 정상 자기소개도 오탐한다. |
| 보정 전 기억을 사용하는 회상 | 생성 입력에서 예산에 따라 기억을 제거해도 grounded_preference_reply에는 원래 memories 인자가 전달된다. | 서버가 모델 입력 밖 기억으로 답변을 보정할 수 있으므로, 모델이 기억했다는 평가에 포함하면 안 된다. 이번 샘플은 기억이 없어 해당 경로가 실행되지 않았다. |

잘못된 과거 assistant 대사도 이후 기록에 남는 구조다. 취향 충돌은 일부 제외하지만 일반 역할 오류를 자동 제거하지는 않는다. 이것이 오류를 지속시킬 가능성은 있지만 실제 개인 대화를 열어 확인하지 않았다.

## 입력 크기와 설정

합성 샘플은 템플릿 포함 1,347토큰, context 4,096, 출력 예약 256, 여유 예약 64, 입력 예산 3,776이다. 잘림 없음. system 단독 토큰화 1,298, 그중 캐릭터 이전 스키마 안내 부분은 447이다. 부분별 토큰 값은 독립 계산이므로 합산용 수치가 아니다. JSON schema가 system 설명과 response_format 양쪽에 존재하며, 중복 제거가 안전한지는 비교 검증이 필요하다.

temperature 0.4, top_p 1.0, top_k 20, presence 0.5, frequency 0.3, repeat_penalty 1.08을 확인했다. 이 값을 역할 오류의 원인으로 단정하지 않는다. 프롬프트 비교에서는 고정한다. 전체 4,096토큰이 실제 역사 길이를 항상 보장하는 것은 아니며 오래된 메모 → 기억 → 오래된 문답 순으로 제거하는 현재 정책을 유지한다.
